# Telephone message editor — 2026-10-20

455 default text/templates and message fragments across original door/create/edit and tenant door/member/zone functions. Owner-only `voice_messages` and `voice_save` actions list, override, and reset defaults. Overrides apply to all customers using the selected function/context; they are not tenant-specific. Native Yemot prompts and vendor-supplied names remain outside this catalog.

`voice(id, parts)` always returns the original text. During an AsyncLocalStorage request it captures concrete dynamic values. `withVoice` runs outside `withAudit`: original business decisions, database/vendor payloads, response classification and call safeguards remain unchanged. Only t- speech segments in the final response are rewritten; read keys, command parameters and statuses are preserved. Evaluated candidates and module-level constants only; longest nonrecursive match wins. A whole-message override wins over overlapping fragment overrides. Messages shared by a helper are shared within that catalog context.

Private RLS table `vendpay_voice_overrides`; anon/authenticated have no privileges. Owner writes validated fixed catalog IDs and exactly-once numbered placeholders. Reserved IVR separators/control characters are rejected. Read failures/timeouts fall back to original text, never replay the handler. No rendered speech, member data or credentials are logged or stored by the customization layer. Edit/reset events contain only metadata in the operation journal.

Validation: existing member/zone/door routing/auth tests pass; summary syntax regression passes. Voice tests cover owner-only writes, placeholder preservation, injection rejection, concurrency isolation, reset, fallback, unchanged business strings and authenticated summary override without writes. Live legacy `action=health` returned a temporary customized message; that temporary override was removed afterward. No actual door or vendor data mutation was used for verification. A physical telephone listen remains user verification.

Source catalog instrumentation script is a one-time migration and refuses to run on already instrumented code. Add future IDs/templates explicitly to the source catalog and relevant deployed function catalog. Keep runtime copies synchronized. Full master catalog is `supabase/functions/vendpay-voice/voice-catalog.ts`; owner API uses full catalog, telephone functions receive only their own entries.
